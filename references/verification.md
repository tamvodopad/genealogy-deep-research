# Доказательность: схема находки, правила «наш / не наш», передача текста

Читать: перед составлением брифов (схему копировать в бриф дословно) и перед шагом проверки.

## Схема находки — одна строка JSON в `units/<id>/findings.jsonl`

```json
{"id": "U03-F07",
 "claim": "В IX ревизии 1850 г. д. Малые Ключи семья 12: Иван Петров Сидоров, 45 л., сын Яков 20 л.",
 "person_ids": ["@I123@"], "place_ids": ["Малые Ключи|вятская губерния"],
 "evidence": [{"source_type": "primary", "title": "IX ревизия 1850, <уезд>, д. Малые Ключи",
               "locator": "<архив> ф. NNN оп. N д. NNNN л. NN об.; кадр 0123", "url": "",
               "access_level": "scan", "excerpt": "Иван Петров Сидоров 45", "seen_at": "2026-10-11"}],
 "identification": "ours", "match_on": ["имя+отчество", "деревня", "возраст ±3", "семья (сын Яков)"],
 "reasoning": "совпадают имя, отчество, деревня, возраст и сын Яков из древа",
 "contradictions": "", "inventory_status": "known", "query_ids": ["U03-Q12"],
 "next_step": "VIII ревизия 1834 — отец Пётр",
 "order": null}
```


Поля:
- `source_type`: `primary` (сам документ эпохи: ревизия, метрика, исповедная, обыск, послужной список; скан карточки/документа, открытый на сайте базы, — тоже `primary`) · `catalog` (опись/каталог: подтверждает существование дела, **не** присутствие предка) · `index` (строка результата поиска в базе, указатель, таблица поисковой группы) · `secondary` (статья, книга, краевед, энциклопедия) · `user_inventory` (то, что уже у пользователя).
- `access_level`: `snippet` (видел только строку поисковой выдачи) · `catalog_entry` (видел строку описи) · `page` (открыл страницу с текстом) · `scan` (видел изображение документа) · `user_inventory`.
- `locator`: URL **и/или** архивный шифр с листом/кадром/номером записи. Без локатора свидетельства нет.
- `excerpt`: дословно, ≤ 25 слов, орфография оригинала.
- `identification`: `ours` (подтверждено) · `probable` · `possible` · `not_ours` (исключено) · `n/a` (находка не о человеке: дело, история места).
- `inventory_status`: `known` (уже есть у пользователя / заказано) · `new` · `unknown` (инвентарь по этому архиву неполон — тогда **не писать new**).
- `archive`: архив, к которому относится находка (для сверки полноты инвентаря `scope`).
- `verified` (заполняет проверяющий на шаге 6): `{"by": "<агент/единица>", "date": "…", "result": "confirmed|downgraded|excluded", "note": "что открыл и что увидел"}`. В `orders.csv` попадают только `confirmed`.
- `order` (если стоит заказать): `{"archive", "cipher", "title", "years", "place", "why", "digital", "price"}` — `price` только с прайс-листа по URL, иначе «уточнить».

Журнал запросов `units/<id>/queries.jsonl`: `{"id","source","query","date","results","opened","note"}` — **каждый** запрос, включая пустые (отрицательный результат — тоже результат).

## Правила (их же проверяет `research_state.py check`)

1. **Шифры и URL — только увиденные в этой работе** (или из инвентаря пользователя: `source_type: user_inventory`, в `locator` — файл/таблица). Номер фонда/описи/дела/листа пишется, только если он виден на открытой странице описи или документа; в `excerpt` — строка описи. Шифр из памяти, из статьи без сноски, из агрегатора без проверки → `source_type: secondary`, в заказы не идёт.
2. **«Подтверждено» (`ours`) = первоисточник на странице или скане + ≥ 2 независимых признака** в `match_on`: имя+отчество, деревня, возраст ±3 (ревизии сдвигают на 1–4 года), семья (жена, дети, братья из древа). Одна фамилия — всегда `possible`, как бы редка она ни была.
3. **Сниппет = максимум `possible`**, с URL, который надо открыть. В отчёте — список «открыть руками».
4. **Каталог ≠ присутствие.** Строка описи «Ревизская сказка д. N» доказывает, что дело есть, а не что там наш предок.
5. **Исключение (`not_ours`) требует обоснования и проверки полноты:** «нет такого сына в сказке» годится, только если сказка по деревне полная (все листы, мужская и женская часть) и годы совпадают; иначе `possible` с пометкой.
6. **Однофамильцы и одноимённые места:** отсеивать клириков, помещиков, чиновников, однофамильцев из соседних уездов; деревню сверять по уезду/волости (одноимённых много, в базах — «Троицкая вол.» в разных уездах).
7. **До 1860-х у многих групп крестьян фамилия нестабильна** (от имени отца/деда, «он же», уличные прозвища) — искать по имени + отчеству + деревне, а фамилию считать слабым признаком.
8. **Известное за новое:** `new` ставится только после сверки с `known.jsonl` и только по архиву со строкой `{"kind":"scope","value":"<архив>","where":"complete"}`; иначе `unknown`.
9. **Проверяющий читает свидетельство, а не пересказ** — открывает `locator`/`url` сам.

## Шкала в отчёте
✅ подтверждено (`ours`) · 🟡 вероятно (`probable`) · ❓ возможно (`possible`) · ✗ не наш (`not_ours`) · ★ ключевая находка · 🆕 новое / ✔ уже было / ◌ инвентарь неполон.

## Передача текста документа
- Орфография оригинала; при необходимости упрощение: ѣ→е, і→и, ѳ→ф, конечный ъ опущен — **указать это в шапке расшифровки**.
- `[слово ]` — неуверенное чтение; `[неразб.]` — не прочитано; `⟦слово⟧` — зачёркнуто; `с[ын]` — раскрытие сокращения.
- Формы имён и фамилий не унифицировать; фамилии, отчества и родство не дописывать; реконструированное — в [скобках].
- Даты смерти в ревизиях — «ок.» (сдвиг 1–4 года); возрасты «взятых из бегов» часто условные.
- Первичную выписку OCR сверять со сканом; помечать «сверено со сканом» и что было неверно.
- Не приписывать источнику слова пересказчика (краевед, статья).
