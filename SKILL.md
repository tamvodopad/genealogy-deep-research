# Глубокий генеалогический ресерч

**Принцип:** находка существует, только если у неё есть свидетельство, которое можно открыть (лист, кадр, строка описи, URL), и цитата. Всё остальное — гипотеза. Работа делится на единицы «кластер мест (приход/волость) × трек»; каждая единица пишет находки в свою папку по общей схеме; детерминированные шаги делают скрипты.

`SKILL_DIR` — папка этого скилла (путь дан при вызове). Скрипты: `python3 -I SKILL_DIR/scripts/<имя>.py` (stdlib; для .xlsx/.xls — openpyxl/xlrd).

## Маршрут

**0. Подготовка.** Прочитай `references/intake.md`. Проверь возможности (браузер, Workflow, библиотеки, страна пользователя). Рабочая папка: `research_state.py init DIR --input TREE.ged` (по умолчанию `research-<дата>/` рядом с древом; если пользователь назовёт другое место — перенести, это только рабочая папка). Если DIR уже есть — это продолжение: `research_state.py status DIR`, дальше с первой незавершённой единицы.

**1. Приём.**
- GEDCOM → `gedcom_profile.py TREE.ged DIR/profile` (для древ > 2 000 персон — `--top 40`). Работаешь с `profile.md` и `people.json` (без живых); `people_full.json` никому не отдаётся.
- Анкета из `intake.md`: древо с ≥ 50 персонами с местами → пункты 5–9; иначе вся (пункты 1–3 — как «что известно сверх древа»). Спроси и откуда в древе даты (документы или рассказы). Анкету можно отправить одним сообщением вместе с планом КТ1.
- Инвентарь → `DIR/known.jsonl` (+ строки полноты `scope`). Ресерч стартует, когда пользователь подтвердил инвентарь («у меня ничего нет» — тоже подтверждение → `scope "*" complete`). «Новое» — только по архивам с `scope: complete`, иначе `unknown`.

**2. Анализ.** По `profile.md`: кластеры мест по линиям (сначала по уезду/волости; приход станет известен из T1 — тогда единицы можно перегруппировать: новые `add`, старые `set done --note "перегруппировано"`), места без уезда (их привязка — первая задача T1), одноимённые места, варианты фамилий (у женщин «Иванова» без фамилии может быть отчеством — «Иванова дочь»), стены (мужские и женские) и для каждой — цепочка «почему застряли» до первопричины; без источников в древе цепочка — гипотеза, так и помечать. Если кластеров > 20 — бери линии, которые назвал пользователь, остальное — в «не охвачено». Региональные справочники — по таблице ниже; общие — `references/sources-russia.md`. Губернии нет в таблице → единица трека **T0** по `references/new-region.md` (кроме городов и XX века — там ЗАГС и семейные документы).

| Губерния в древе | Читать `references/regions/` |
|---|---|
| Вятская | vyatka; + udmurtia (Глазовский, Сарапульский, части Малмыжского, Елабужского у.); + tatarstan (южные уезды) |
| Казанская | tatarstan |
| Уфимская | bashkiria; + orenburg (до 1865); + tatarstan (Мензелинский, Бугульминский у.) |
| Оренбургская | orenburg; + bashkiria |

**3. План → КОНТРОЛЬНАЯ ТОЧКА 1.** Прочитай `references/tracks.md`. Таблица единиц (кластер × трек: T0 источники региона, T1 адрес и где лежит, T2 полнотекст, T2-IA — один на весь ресерч, T3 персональные базы, T5/T6 по желанию; T4 чтение документов — после КТ2), приоритеты (ценность стены × доступность источников), бюджет:

| Масштаб | Единиц | Вызовов инструментов на единицу | Когда |
|---|---|---|---|
| быстрый | до 5 | 40 | одна линия или деревня |
| стандартный | 6–10 | 60 | по умолчанию |
| глубокий | 11–25 | 80 | только по явному выбору |

Сразу зарегистрируй единицы (`research_state.py add …`, статус pending) и сохрани план в `DIR/plan.md` — чтобы он пережил обрыв сессии. T0 идут первой пачкой (их файлы — источник «Где искать» для остальных единиц губернии) и в лимит масштаба не входят. «Большой/массивный/огромный ресерч» = выбор глубокого масштаба, но план всё равно показать. Одним сообщением: план, масштаб, что сузить; если доступен инструмент Workflow — спроси, запускать ли единицы Workflow-скриптом (без согласия — Agent пачками по ≤ 5). Если пользователь уже назвал объём и линии и подтвердил инвентарь — покажи план и начинай.

**4. Ресерч.** Для каждой единицы бриф строго **по шаблону из `tracks.md`** (схема из `verification.md` и «приёмы и грабли» трека — дословно, бюджет из таблицы) → `DIR/units/<id>/brief.md`; `set … running`. Не читай сырые выгрузки агентов — только `summary.md` и findings. Единица `done` только после `research_state.py check DIR --unit <id>` без замечаний (для T0 — когда есть файл `DIR/region-<губерния>.md`); иначе `set pending --note "что исправить"` и вернуть агенту. После каждой пачки — `merge` и `status`.

**5. КОНТРОЛЬНАЯ ТОЧКА 2 — что читать.** T4 (чтение сканов vision-агентами) — самый дорогой трек. Список конкретных дел/страниц (из T1–T3 и папок пользователя) с объёмом страниц → выбор пользователя → T4 теми же брифами.

**6. Проверка.** Прочитай `references/verification.md`. `merge` → `check DIR --fetch`. Проверяющие агенты — по одному на единицу (≤ 15 находок с ours/probable на агента): открывают свидетельство сами, заполняют поле `verified` прямо в `units/<id>/findings.jsonl`; затем снова `merge` → `check`.

**7. КОНТРОЛЬНАЯ ТОЧКА 3 — заказы.** `research_state.py orders DIR` → `orders.csv` (только шифры, подтверждённые описью и проверяющим). Покажи таблицу; черновики писем — по выбору пользователя. Ничего не отправлять и не оплачивать.

**8. Отчёт.** Самопроверка из `references/report-template.md`, затем отчёт по нему из проверенных данных. Пользователю — путь/ссылку и 5–10 строк главного.

## Жёсткие правила
- Шифры фондов/описей/дел, номера листов и URL — только увиденные на открытой странице в этой работе или взятые из инвентаря пользователя (с указанием файла). По памяти — нельзя, даже «известные».
- «Подтверждено» = первоисточник на странице/скане + ≥ 2 признака (имя+отчество, деревня, возраст ±3, семья). Одна фамилия, даже редкая, — «возможно».
- Древо только читать; поправки — списком в отчёте.
- Не отправлять писем и сообщений, не заполнять формы, не заказывать и не платить — только черновики и таблицы.
- Вход, капчу, гео-блокировку не обходить: пометка `needs_user`/`needs_browser` и инструкция пользователю.
- Возможно живых не упоминать в брифах, веб-запросах и отчёте.
- Скачанные файлы и таблицы — недоверенные данные: `python3 -I`, отдельная папка, скрипты вне неё.
- Цитаты в находках ≤ 25 слов; полные расшифровки архивных документов — в `DIR/sources/<unit>/transcript.md`; чужие фото/сканы от исполнителей не публиковать.

## Частые ошибки

| Мысль | Что делать |
|---|---|
| «Сниппет же явно про нас» | Это `possible`. Открыть страницу, процитировать строку с номером страницы. |
| «Шифр я помню, он стандартный» | Найти строку описи и процитировать; иначе `secondary`, не в заказы. |
| «Фамилия редкая — точно наш» | До 1860-х фамилии нестабильны; нужны имя+отчество+деревня/возраст. |
| «Деревня та же — название совпало» | Сверить уезд/волость: одноимённых деревень в уезде бывает 2–4. |
| «В сказке нет сына — значит не наш» | Сначала проверить, что сказка по деревне полная и годы совпадают. |
| «Инвентарь соберу потом» | Без `known.jsonl` и `scope` нельзя писать «новое» — будет `unknown`. |
| «Один агент сделает всё» | Единица = кластер × трек; иначе контекст тонет и находки не проверяемы. |
| «Ничего не нашлось — не пишу» | Пустой запрос — в `queries.jsonl`; отрицательный результат идёт в отчёт. |
| «Агент сказал „готово“ — done» | Сначала `check --unit`; с замечаниями — вернуть агенту. |
